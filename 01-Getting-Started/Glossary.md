# Common IAM Terminology

## Overview

Identity & Access Management (IAM) introduces terminology that appears throughout enterprise identity systems. Understanding these terms provides a common language for discussing authentication, authorization, provisioning, governance, and troubleshooting.

This glossary focuses on practical enterprise terminology rather than vendor-specific definitions.

---

## Identity

A digital representation of a person, device, application, or service within an organization.

An identity contains attributes that describe the object and determine how access is managed.

Examples:

- Employee
- Contractor
- Service Account
- Application
- Device

---

## Account

A representation of an identity within a specific application.

One identity may own multiple accounts.

Example:

One employee may have accounts in:

- Microsoft 365
- AWS
- Salesforce
- Slack
- GitHub

---

## Identity Provider (IdP)

A system responsible for authenticating users and issuing identity information to applications.

Examples:

- Okta
- Microsoft Entra ID
- Ping Identity

---

## Service Provider (SP)

An application or service that relies on an Identity Provider for authentication.

Examples:

- AWS
- Salesforce
- Slack
- GitHub
- Microsoft 365

---

## Authentication

The process of verifying a user's identity.

Authentication answers:

> **Who are you?**

---

## Authorization

The process of determining what an authenticated user is allowed to access.

Authorization answers:

> **What are you allowed to do?**

---

## Federation

The trust relationship that allows one system to accept authentication performed by another system.

Federation enables Single Sign-On (SSO).

---

## Single Sign-On (SSO)

A user experience that allows one successful authentication to provide access to multiple connected applications.

---

## Multi-Factor Authentication (MFA)

Authentication that requires two or more independent verification factors before access is granted.

Common factors include:

- Password
- Mobile push notification
- Security key
- Biometrics
- Passkey

---

## Assertion

A package of identity information generated by the Identity Provider after successful authentication.

Assertions are commonly used in SAML federation.

---

## Claims

Identity information contained within a token or assertion.

Examples:

- Username
- Email
- Department
- Groups
- Roles

Applications use claims during authorization.

---

## Token

A digitally signed credential issued after successful authentication.

Common token types include:

- ID Token
- Access Token
- Refresh Token

OAuth 2.0 and OpenID Connect primarily use tokens.

---

## Role-Based Access Control (RBAC)

An authorization model that grants permissions based on organizational roles instead of assigning permissions directly to individual users.

---

## Least Privilege

A security principle stating that identities should receive only the minimum permissions required to perform their responsibilities.

---

## Provisioning

The automated process of creating, updating, suspending, or removing identities and application accounts.

Provisioning consists of two related processes:

- Identity Provisioning
- Account Provisioning

---

## SCIM

System for Cross-domain Identity Management.

An open standard used to automate user account provisioning and lifecycle management across supported applications.

---

## Profile Mastering

The process of determining which connected system is the authoritative source for a specific identity attribute.

---

## Attribute

A piece of information describing an identity.

Examples include:

- Name
- Email
- Department
- Manager
- Job Title
- Employee ID
- Employment Status

---

## Group

A collection of identities that share common characteristics or access requirements.

Groups simplify access management by assigning permissions collectively rather than individually.

---

## Directory Services

A centralized repository that stores identities, groups, and organizational information.

Examples:

- Active Directory
- LDAP
- Microsoft Entra ID

---

## Identity Lifecycle

The complete lifecycle of an identity from creation through modification and eventual removal.

Common lifecycle stages:

- Joiner
- Mover
- Leaver

---

## Identity Governance

The processes and controls used to ensure identities maintain appropriate access throughout their lifecycle.

Examples include:

- Access Requests
- Manager Approvals
- Access Reviews
- Certifications
- Separation of Duties

---

## Adaptive Authentication

An authentication approach that evaluates contextual signals before determining authentication requirements.

Signals may include:

- Device
- Location
- Network
- User Behavior
- Risk Level

---

## Identity Engine

The policy evaluation engine responsible for making authentication and identity lifecycle decisions.

Typical responsibilities include:

- Authentication policy evaluation
- Risk evaluation
- Group rule evaluation
- Identity lifecycle automation

---

## Key Takeaways

- An **identity** represents who the user is.
- An **account** represents where the user exists.
- **Authentication** verifies identity.
- **Federation** shares authentication between trusted systems.
- **Authorization** determines access.
- **Provisioning** manages identities and accounts.
- **Governance** ensures access remains appropriate over time.
